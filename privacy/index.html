CViper Light

Privacy policy

There is no account, no server of ours, and no analytics. Your CV, your saved jobs and your applications sit on your own device. We receive nothing.

For CViper Light 0.1.0. This page mirrors the policy the app generates from its own list of the addresses it may contact — the same list the app shows under Settings → Privacy, and the one a test holds its code to. It changes when that list changes, and not otherwise.

The short version. CViper Light has no account to create, no server of ours behind it and no analytics in it. Your CV text, your saved jobs and your applications are stored on your own device, in a database that belongs to the app. The app contacts another service only when you press a button that says it will, and only the services listed on this page.

We — the people who make CViper Light — receive nothing from it. Not your CV, not your searches, not your keys, not whether you use it at all.

What the app keeps, and where

Everything is on your own device. There is nowhere else for it to be.

  • Your jobs, applications, CV text and every analysis — one database file, cviper.db, in this app's data folder for your user account.
  • Your API keys — this device's credential store: Credential Manager on Windows, the Keychain on an iPhone, iPad or Mac, the Secret Service on Linux. One entry per key. The app cannot read a key back into the screen, so if you forget one you paste a new one.
  • Which job boards you enabled and how you ordered them — job-boards.json in the same data folder.
  • Small conveniences: your last search, today's request count, and that you have seen the introduction — the app's own browser storage, which no other program reads.

Nothing is sent anywhere on its own

The app makes no request when you open it. It does not phone home, and it does not even check for its own updates unless you press the button. Every request it makes is one you started: a job search, a CV check against a provider you chose, an update check you pressed, or a job advert you asked it to fetch.

There is no telemetry — not "anonymous statistics", not crash reports, none. The Settings screen has a switch showing this, permanently off, and a test fails the app's build if any code ever reads it as on.

Every address the app can contact

This is not a summary. It is the exact set of addresses the code is allowed to name; a test fails the app's build if one is added without appearing on this list.

Sent with your own key, when you ask

These carry a key you pasted into Settings, under an account that is yours. The bill, if there is one, is between you and that provider.

  • api.openai.com — A CV analysis you start, sent with your own OpenAI key under your own OpenAI account.
  • api.anthropic.com — A CV analysis you start, sent with your own Anthropic key under your own Anthropic account.
  • api.adzuna.com — A job search you start, sent with the free Adzuna key you registered yourself.
  • www.reed.co.uk — A job search you start, sent with the free Reed key you registered yourself. Reed's developer page is also opened in your browser from Settings.

Only when you press a button, with no key

A plain request with nothing about you in it beyond the request itself.

  • github.com — The update check reads a small signed file from this app's public GitHub releases. It happens when you press "Check for updates", and carries no data about you beyond the request itself. The source code is also opened in your browser from Settings → About.

Opened in your browser, never by the app

The app hands the address to your own browser and is not involved from then on. What that site sees is what your browser shows it. No tracking parameters are added.

  • developer.adzuna.com — The page where you register your own Adzuna key. Opened in your browser from Settings; the app does not load it.
  • platform.openai.com — The page where you create your own OpenAI API key. The welcome screen and the OpenAI card in Settings hand the address to your browser when you tap it; the app never loads it, and nothing is added to the link.
  • www.linkedin.com — A keyless search link for LinkedIn.
  • uk.indeed.com — A keyless search link for Indeed.
  • www.totaljobs.com — A keyless search link for Totaljobs.
  • www.cv-library.co.uk — A keyless search link for CV-Library.
  • www.adzuna.co.uk — A keyless search link for Adzuna's public search.
  • www.google.com — A keyless search link for Google Jobs.
  • jobs.theguardian.com — A keyless search link for Guardian Jobs.
  • www.jobserve.com — A keyless search link for Jobserve. The app never loads the page, and it never scrapes Jobserve.
  • cviper.ai — The full CViper, and the page about this app. A few one-line signposts and the About entry in Settings hand the address to your browser when you tap them; the app never loads it, and nothing is added to the link.

Each keyless job-board link is read from job-boards.json. Pressing one hands the address to your own browser; the app never loads the page.

Stays on this computer

A program running on this same machine. The request never reaches the internet.

  • 127.0.0.1 — Ollama, if you installed it. The request goes to a program on this computer, not to the internet.
  • localhost — Named only so the fetch-from-link guard can refuse it. Never contacted.

The one page you ask it to fetch

When you paste a job advert's link and press Fetch, the app opens that one page, the same as your browser would. The site sees your IP address, exactly as it would if you had clicked the link yourself. It opens exactly one page: it does not follow links, does not crawl, and does not load images, adverts or trackers. It carries no cookies, no sign-in and no API key — it cannot even reach your saved keys. Addresses on your own computer or home network are refused before anything is sent. Nothing is sent to us, because there is no server of ours to send it to.

Services you may choose to use

If you paste an API key for OpenAI, Anthropic, Adzuna or Reed, the app sends the request you start to that service under your own account, and that service handles what it receives under its own privacy policy, not this one. The key itself is stored in your device's credential store, and the app has no way to read it back into the screen.

If you run Ollama, the analysis goes to that program on the same device and not to the internet.

A keyless job-board link is handed to your own browser. What that site sees is what your browser shows it; the app is not involved from then on.

Taking your data with you

Everything lives in one database file in the app's own data folder. Settings exports the whole thing as a single readable .json file, wherever you choose to put it, and imports it back. A CV that arrived as a JSON Resume can also go back out on its own, so it can go into any tool that reads the format.

Import merges rather than overwrites: records with the same id are updated and nothing is ever deleted, which the confirmation screen says before it writes anything.

Deleting your data

Settings → Delete everything removes the database, every saved key and the preferences, and the app returns to its first-run state. A test fails the app's build if a new table or store is left out of it.

Do that before uninstalling if you want the keys gone as well: on some systems the credential store keeps an app's entries after the app itself is removed.

This website

cviper.ai sets no cookies, runs no analytics and makes no third-party requests. There is no font, script, image or tracker loaded from anywhere else — everything you are reading is served from this domain. Our host, GitHub Pages, keeps its own server logs of requests; we do not read them and cannot connect them to anything in the app.

Children

CViper Light is a job-application tool and is not directed at children under 13. It collects no data from anyone.
